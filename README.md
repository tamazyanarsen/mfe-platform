# MFE platform

[English](README.en.md) · Русский

Платформа для приложений из многих независимых микрофронтендов: каждый ремоут деплоится
отдельно, команды обновляют версии независимо, хост собирает их в одно приложение.

- **Контракт вместо бриджа.** Ремоут — кастомный элемент плюс манифест и идемпотентная
  `register()`. Хост монтирует любой ремоут одинаково: на rwc, на React, на чём угодно.
- **Несколько версий UI-кита на одной странице.** Реестр выдаёт постфикс тегов по линии
  совместимости кита (`rwc-button-v0-1` рядом с `rwc-button-v0-2`), ведёт учёт, кто какую
  версию использует, и применяет политики.
- **Хост владеет историей.** Таблица маршрутов строится из манифестов до загрузки кода
  ремоутов; код грузится при первом переходе или заранее, при наведении на ссылку. Обычные
  ссылки в ремоутах работают без перезагрузки страницы.
- **Падение ремоута не роняет страницу.** Ошибка загрузки или отрисовки остаётся внутри
  `<mfe-outlet>`, событие уходит в транспорт наблюдаемости, кнопка «Повторить» загружает
  ремоут заново.
- **Конфигурация при запуске.** Список ремоутов, навигация и обзор — JSON-файл рядом с хостом:
  новый ремоут подключается выкладкой файла, без пересборки хоста.
- **Инструменты для команд.** Новый ремоут одной командой, тест контракта без хоста, подмена
  ремоута на локальный прямо в стенде или проде, панель отладки на странице.
- **Проверка целостности.** Цепочка хешей от конфигурации хоста до каждого чанка ремоута:
  подменённый на CDN файл не исполняется.
- **Права на общее состояние.** Какой ремоут какие поля стора может менять — в конфигурации
  хоста; по умолчанию сессию не меняет никто.
- **Делится только совместимое.** Рантайм Module Federation — у хоста, UI-кит — один на линию
  совместимости, без singleton: команды обновляются независимо.
- **Без сети.** Рантайм не делает запросов, кроме загрузки кода ремоутов и конфигурации по
  вашим адресам: ни телеметрии, ни CDN, ни шрифтов.

Ядро (`contract`, `host-runtime`, `registry`, `bus`) не зависит ни от одного UI-фреймворка —
это проверяется в CI. rwc и React подключаются равноправными адаптерами.

Чем это лучше обычной схемы «React-хост + Module Federation с shared React» и где обычная
схема выгоднее — [docs/comparison.md](docs/comparison.md).

## Расширение

Ядро расширяется без форка через три точки: `ObservabilityTransport` (куда уходят события
монтирования и регистрации), `PolicyHook` (запрет монтирования или регистрации версии кита)
и `manifest.extra` (произвольные метаданные ремоута). Подробно — [docs/contract.md](docs/contract.md).

## Быстрый старт

Нужны [bun](https://bun.sh) 1.4+ и Node.js 20.19+ или 22.12+ (требование Rsbuild).

```bash
bun install
bun run dev
```

Откройте <http://localhost:3000>. На странице обзора рядом работают два ремоута на rwc с
разными версиями UI-кита; в навигации есть ремоут на React. **Alt+Shift+D** открывает панель
отладки: ремоуты, время загрузки, версии кита, ошибки. В консоли браузера:

```js
mfe.events()              // события монтирования: время загрузки, ошибки, manifest.extra
mfe.registry.records()    // какие версии кита зарегистрированы и кем
```

Новый ремоут:

```bash
bun run create:remote cards --template rwc --title "Карты"   # vanilla | rwc | react
bun install && bun run dev                                   # http://localhost:3000/cards
```

Проверки:

```bash
bun run ci                          # границы пакетов, линт, типы, unit-тесты, сборка, бюджет размера
bun run check:templates             # шаблоны create:remote генерируются, тестируются, собираются
bunx playwright install chromium    # один раз
bun run test:e2e                    # сквозные тесты стенда (dev)
bun run test:e2e:prod               # production-сборка: целостность, общий кит и рантайм
```

## Структура

```
apps/
  host/               оболочка: роутинг, стор; public/platform.config.json — ремоуты и навигация
  mfe-accounts/       ремоут на rwc, @rwcjs/ui 0.2.0-next
  mfe-payments/       ремоут на rwc, @rwcjs/ui 0.1.0
  mfe-legacy-react/   ремоут на React
  mfe-probe/          тестовый ремоут для e2e: вторая сборка на линии кита payments
packages/
  contract/           типы контракта, манифест, навигация, темы шины, точки расширения
  host-runtime/       <mfe-outlet>, загрузчик MF, роутер, ссылки, конфигурация, подмены, транспорты
  registry/           версионированная регистрация тегов
  bus/                типизированная шина и стор
  adapter-rwc/        регистрация кита через реестр, подписки на шину из render()
  adapter-react/      кастомный элемент-обёртка для React-компонента
  testing/            mountRemote, checkRemote — тесты ремоута без хоста
  devtools/           панель отладки на странице
templates/            шаблоны create:remote: vanilla, rwc, react
config/               сборка ремоута: общие модули, хеши целостности
e2e/, e2e-prod/       сквозные тесты dev-стенда и production-сборки
docs/                 архитектура, контракт, разработка, миграция
```

## Подключить ремоут

1. Ремоут экспонирует через Module Federation два модуля: `./manifest` (лёгкий, без
   фреймворка) и `./entry` (`manifest` + `register()`). Проще всего начать с
   `bun run create:remote`. Подробно — [docs/contract.md](docs/contract.md).
2. Хост узнаёт о нём из `apps/host/public/platform.config.json`: имя и адрес
   `mf-manifest.json`, при желании — пункт навигации и место на странице обзора. Файл читается
   при запуске: ни код хоста, ни его сборка не меняются.

Существующую сборку Module Federation перевести на контракт — [docs/migration.md](docs/migration.md).
